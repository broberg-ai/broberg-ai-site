# F011.1 — Tekst-tokens op til WCAG AA, og `.lead` respekterer linjeskift

> Motivation, målinger og non-goals står i epikkens plan:
> [`F011-farvekontrast-og-linjeskift.md`](./F011-farvekontrast-og-linjeskift.md).
> Her står kun HVAD der konkret blev bygget og hvordan det er bevist.

## Ændringer

**`src/styles/brand.css`**

| | værdi | kontrast mod egen baggrund |
|---|---|---|
| `:root --blue-text` | `#00b2ff` (= `--blue`) | 6,22:1 |
| `[data-theme="light"] --blue-text` | `#0a6d9e` | 5,30:1 (var 3,06) |
| `[data-theme="light"] --orange-text` | `#c93a16` | 4,77:1 (var 4,47) |

21 × `color: var(--blue)` → `var(--blue-text)`. 13 × `border-color: var(--blue)`
urørt, ligesom alle `background`/`fill`/`--blue-glow`/`--blue-light`.

`.lead` får `white-space: pre-line`.

**`src/components/widgets/UniverseDiagram.tsx`** — nodens farve delt i TEKST
(`--blue-text`/`--orange-text`) og GRAFIK (`--node-glow`), så glødet beholder
brandfarven mens etiketten bliver læsbar.

## Bevis

**Automatisk** — `src/css-tekst-kontrast` i `src/css-tokens.test.ts`:

| mutation | udfald |
|---|---|
| `--orange-text` → `#cf3f1b` (4,47) | RØD: `4.47:1` mod `4.50:1` |
| `white-space: pre-line` fjernet | RØD |
| gendannet | 6 grønne |

Meldingen bærer **begge tal**, så en rød kørsel siger hvad der skal rettes til —
ikke bare at noget er galt.

**I browseren** — Lens mod det levende site:

| flade | før | efter |
|---|---|---|
| `/flagskibe/lens` | 65 høje | 1 |
| `/universet` | 84 høje | 7 → ~0 efter orange-tokenen |

**Porte:** typecheck 0 · test 0 · gate:text 0 · gate:testids 0 · gate:coverage 0 ·
gate:cms-text 0. `gate:editable` er post-deploy og kørte grønt i CI.

## Ikke verificeret

**Mørkt tema er regnet, ikke fotograferet.** `lens_capture` har ingen parameter for
farvetema. For blå kan mørkt ikke regressere (`--blue-text` **er** `--blue` der);
for orange er 4,28 → 5,23 udregnet med WCAG-formlen.
