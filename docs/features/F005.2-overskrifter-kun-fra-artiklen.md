# F005.2 — Overskrifter redigeres kun fra artiklen

Christian, 31. august 2026: **«overskrifter skal kun kunne redigeres fra
artiklen.»**

## Hvad beslutningen løser

[F005](F005-redigeret-overskrift-viste-tags.md) afdækkede at samme felt blev
behandlet forskelligt to steder:

| Flade | Markering | Hvad et gem skrev |
|---|---|---|
| artiklen | `cmsHtmlAttrs` (rich) | HTML — kursiven overlever |
| kortlisterne | `cmsAttrs` (almindelig) | ren tekst — **kursiven slettes tavst** |

En redaktør der rettede en tastefejl fra et kort ville altså miste en
fremhævning uden en advarsel nogen steder. Det er den samme fejlfamilie som
`@broberg/cms-inline-edit` 0.4.21/0.4.23 og sanneandersen F049.1: **et
almindeligt felt gemmer `textContent`, og markup findes ikke i `textContent`.**

Med én vej ind kan formateringen ikke gå tabt.

## Værktøjet var enigt i forvejen

`cms check-editable` (Gate A.1) har reglen indbygget:

```js
if (el.closest('a[href]')) continue; // inside a link → preview/card;
                                     // the canonical editable copy is the linked page
```

At fjerne `cmsAttrs` fra kort-titler giver derfor **ingen** nye dækningshuller.
Ændringen bringer koden i overensstemmelse med en regel porten allerede
håndhævede — hvilket er den behageligste slags beslutning: den var allerede
husets, den var bare ikke ført igennem.

## Ændret

`cmsAttrs(…, "title")` fjernet tre steder: kategorisidens kort
(`routes.tsx`), seneste-pr-kategori (`routes.tsx`) og forsidens tre kort
(`sections.tsx`). Manchetten (`excerpt`) er urørt — beslutningen gælder
overskrifter.

## Målt live efter udrulning

```
kategorisiden: h3 med data-cms-field: 0 af 8
forsiden:      h3 med data-cms-field: 0 af 3
artiklens h1 redigerbar: True | viser <em>: True
cms check-editable: 97 sider · 0 gap(s)
```
