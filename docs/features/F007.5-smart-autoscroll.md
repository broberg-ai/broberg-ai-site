# F007.5 — Smart auto-scroll i Aidan-chatten

## Motivation

Ejer-rapporteret defekt (Christian 4/9-2026): «Hvis man kommer til at starte med at scrolle op mens chatten stadig skriver så blinker teksten så underligt.» Årsag målt i koden: hver SSE-delta i `spoerg()` (enhance.ts) sætter `msgs.scrollTop = msgs.scrollHeight` ubetinget — brugerens opadgående scroll og chattens nedtvingning kæmper om samme scrollbar, hvilket ligner blink/hop.

## Løsning (godkendt: «Ja byg det»)

Standarden fra gode chat-UI'er (iMessage/Slack-princippet):

1. **Følg kun med når brugeren står i bunden.** En `foelger`-tilstand opdateres på msgs' scroll-event via ren funktion `erNaerBunden(scrollTop, clientHeight, scrollHeight, margin=48)` i `aidan-samtaler.ts` (testbar uden DOM).
2. **Scrollet op + nyt indhold → «↓ Nyt svar»-pill** (absolut positioneret over inputfeltet, `data-testid="aidan-nyt-svar"`). Klik = hop til bunden + følg igen. Egen scroll til bunden skjuler den også.
3. **Tvungne scroll bevares** hvor brugeren selv handlede: egen besked sendt, samtale genindlæst (Fortsæt/historik-valg), Ny samtale.

## Scope

- `src/client/aidan-samtaler.ts`: `erNaerBunden()` + tests
- `src/client/enhance.ts`: `foelger`-tilstand, `rulNed(tving?)` erstatter alle rå `scrollTop`-sætninger, scroll-listener, pill-klik
- `src/components/AidanWidget.tsx`: pill-markup, tekst fra globals (`aidanNytSvar`, da+en — hard rule: tekst bor i CMS)
- `src/styles/brand.css`: pill-styles m. hover/active/focus + eksplicit `[hidden]`-regel

## Non-goals

- Ingen ændring af selve streaming-protokollen eller rendereren
- Ingen scroll-persistens på tværs af genindlæsninger

## Verifikation

Unit-tests på `erNaerBunden`; fuld suite + tsc; Lens-E2E på det levende site: send besked, scroll til top under streaming, assert scrollTop forbliver i top (ingen kamp), pill synlig, klik → bund. Deploy via grøn port (F302).
