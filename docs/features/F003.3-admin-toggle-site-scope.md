# F003.3 — Kontakten på /admin har aldrig virket

**Status:** in progress · **Parent:** [F003 Inline-edit — fuld coverage](./F003-inline-edit-full-coverage.md) · **Fundet:** 2026-08-24, fra cms-siden, mens den samme side blev bygget til webhouse.dk

## Målt før noget blev rørt

Med et rigtigt redigerings-token for broberg-ai, mod produktionen:

```
POST /api/inline-edit/toggle                  → 403  "scoped to … its own site"
POST /api/inline-edit/toggle?site=broberg-ai  → 200  {"enabled":true}
```

Og i den udrullede JavaScript-pakke på broberg.ai:

```
inline-edit/status?site=${t.siteId}     ← har den
inline-edit/toggle                      ← har den IKKE
```

Serveren skal vide hvilket site den taler om, ellers afviser den. Kontakten på broberg.ai/admin har derfor aldrig kunnet tænde eller slukke noget.

## Den anden halvdel: den siger ingenting

```js
if (res.ok) { paintToggle(body.enabled) }   // og ingen else
```

En afvisning efterlader kontakten præcis hvor den stod, uden en lyd. Det er derfor fejlen har kunnet ligge upåagtet: det ligner bare at man ikke ramte knappen. Husreglen om at hver knap skal give besked — også når det går galt — findes for lige denne situation.

## Rettelsen

1. Send `?site=` med, hentet fra den `CMS`-konstant filen allerede har. Én kilde, ikke en ny streng.
2. Vis en fejl når det mislykkes, og lad kontakten stå på serverens sandhed — ikke på det brugeren forsøgte.

## Bevis

Se acceptkriterierne. Kernen: efter klikket spørges SERVEREN om den nye værdi. En kontakt der maler sig selv kan lyve om at have gemt noget — præcis den fejlform husreglen om gem-felter handler om, og her har den stået live i uger.
